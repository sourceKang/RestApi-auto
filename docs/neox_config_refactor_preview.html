NeoX Config 自動化測試重構預覽

這份 HTML 是修改前的設計預覽，不代表程式碼已經套用。目標是先把「目前寫法」和「預計修改後寫法」放在同一頁比較。

主要目標 讓測試檔只描述測試流程，細節搬到 helper/service。
低風險原則 不改 case id、不移除 --run-neox-config 保護、不主動跑 live tests。
驗證方式 重構後先跑 Python compile check，再視需要跑指定 pytest。

預計修改後的資料流

目前資料流是合理的，重構重點是把散在測試檔內的 CLI/token/report 邏輯集中。

configs/neox_config
JSON/YAML 測試資料與 reference
services/neox_config
target、path、payload、profile metadata
tests/support
SSH CLI、report、共用 assertion helper
tests/test_neox_*.py
測試流程與 pytest parameterization
reports
device verification JSON 產物

建議實作順序

  • 先抽共用純函式：normalize_cli_output、GE/VLAN/ONT expectation helpers。
  • 再抽 profile expected token mapping，保持測試行為不變。
  • 最後才整理 service.py 的常數與 payload helper，避免一次移動太多造成 import 風險。
  • 每一步跑 compile check；不自動跑會動設備的 NeoX live tests。
